# 手势交互虚拟 DJ

一个计划使用笔记本内置摄像头，在浏览器本地追踪双手、操作虚拟 DJ 控件并播放本地音乐的项目。

## 使用入口

开发进度、认领、验证结果和接续步骤统一维护在 [进度与接续记忆](docs/PROGRESS.md)。本文件介绍项目目标和使用方法；下文的最终目标不表示功能已经全部交付。

## 最终目标

- 使用笔记本内置摄像头，在网页摄像头画面中显示看起来放置在桌面上的虚拟 DJ 面板。
- 允许手动调整屏幕角度、摄像机位和面板四角，不要求自动识别、自动贴合或持续追踪桌面。
- **支持双手同时操作不同控件**：首先实现一只手调音量，另一只手调低通滤波，互不抢占。
- 从本地选择 MP3、常见 PCM WAV 等浏览器可解码的音频，通过手势播放、暂停和调节参数。
- 在两位开发者各自的笔记本上，使用桌面版 **Microsoft Edge** 完成约 10 分钟的实际体验验收。

“桌面投影”指摄像头画面中的虚拟叠加效果。项目不使用实体投影仪，物理桌面本身不会发出控件图像；也不要求识别真正的指尖触桌。

## 分步实现

| 阶段 | 交付内容 |
| --- | --- |
| 摄像头实验 | 预览、手部骨架、指尖、诊断数据；从一开始就检查未来双手所需的活动范围 |
| 单手交互实验 | 可移动、缩放的二维矩形面板，捏合按钮和推子 |
| 阶段 MVP | 本地单曲加载、播放／暂停、音量，单手可用 |
| 必做桌面阶段 | 四角手动透视校准、正确的反向命中映射、低通滤波 |
| 必做双手阶段 | 双手独立抓取不同控件，处理交叉、丢手和恢复，完成最终实机验收 |

**单手和二维矩形面板只是中间 MVP，不能作为整个项目完成的标准。** 双音轨混音、搓碟、自动对拍、丰富的 3D 场景与动画可继续扩展，不阻塞上述基础终态。

默认操作是食指定位、捏合抓取、移动拖动、松开释放。丢手时冻结对应控件，音乐保持当前状态；恢复后先松手，再重新抓取。鼠标与键盘保留用于首次启用、校准和后备控制。

## 技术方向与本地处理

采用 Vite、React、TypeScript、MediaPipe Tasks Vision 和 Canvas 2D；模拟模式用 SVG 展示离散骨架。Web Audio API、桌面透视与双手控件按阶段接入；当前不依赖 Tone.js 或 Three.js。

摄像头图像、手部识别和音乐处理均在本地完成。运行时不上传媒体、不申请麦克风；模型和 WASM 与应用资源一起本地提供。首次安装依赖、取得模型等开发准备仍可能需要联网。本地开发服务器用于提供网页资源，不是音乐上传服务器。

Edge 是正式验收目标，兼容性与性能按项目计划进行设备实验。约 10° 的俯角只是候选机位，不是硬性要求或效果保证；实际验证结果见进度文件。

## 本地运行与检查

统一使用 **Node 24.19.0、npm 11.17.0**。`.node-version`、`package.json` 和唯一的 `package-lock.json` 记录工具链；`.npmrc` 将 npm 缓存放在被忽略的 `.cache/npm`，避免依赖个人全局缓存权限。

Windows 上重新执行 `npm ci` 前先停止正在运行的开发／预览服务，避免原生构建模块被进程占用。

在包含 S0 工程的仓库目录运行：

```sh
npm ci
npm run dev
```

如果全局版本不同，可以临时使用指定版本，命令仍在仓库根目录执行：

```sh
npm exec --yes --package=node@24.19.0 --package=npm@11.17.0 -- npm ci
npm exec --yes --package=node@24.19.0 --package=npm@11.17.0 -- npm run dev
```

首次 `npm run dev` 或 `npm run build` 会从固定地址准备模型并校验 SHA-256，随后复制安装包内的 WASM 到被忽略的 `public/tracking/`；缓存命中后可离线使用。也可以提前运行 `npm run prepare:tracking`。准备失败时按错误提示检查网络并重试，不使用运行时 CDN。

打开终端打印的 localhost 地址，默认是 `http://localhost:5173/`。端口占用会明确失败，可用 `npm run dev -- --port 5174` 指定其他端口。页面初始不申请设备权限；点击“开启摄像头”后只申请视频权限。

## 实验台操作

- 摄像头模式：先选请求分辨率、GPU 优先／CPU、单手／双手，再开启摄像头。右侧显示取得的视频设置与本轮诊断；请求值不等于实际值。
- GPU 初始化或运行失败会尝试 CPU，界面明确提示，计量重新开始；更改配置需先停止，再重新开启。
- 停止、切换输入或隐藏页面会释放视频轨道和识别进程；返回页面后手动重新开启。停止后保留本轮汇总，重新开启清零。
- 模拟输入：选择零／一／两只手，生成下一帧或重置。此模式不申请摄像头权限、不计算追踪性能。
- 手部颜色只区分模型左右分类，食指尖带圆环；不表示已经建立稳定手部身份，也不检测真实触桌。

诊断按已返回帧统计完整、有限、全部入镜的 21 点；双手配置要求同帧两手有效。频率是识别就绪后本轮有效结果数／累计运行秒数，包含无手片段；忙时跳帧，不排队。p50／p95 使用 1 ms 桶的累计直方图，10,000 ms 桶表示该值及以上。正式比较需在固定机位和手均处于有效区域的片段中分别开启新会话；这些软件测量不代表动作到声音的端到端延迟。

| 命令 | 用途 |
| --- | --- |
| `npm run prepare:tracking` | 准备并校验本地模型、复制固定版本 WASM |
| `npm run typecheck` | TypeScript 严格检查 |
| `npm run lint` | ESLint，警告也视为失败 |
| `npm test` | 一次性运行数据逻辑测试 |
| `npm run test:watch` | 开发时监听测试 |
| `npm run build` | 类型检查并构建到 `dist/` |
| `npm run preview` | 预览已构建页面，默认 localhost 端口 4173 |
| `npm run check` | 顺序运行类型、lint、测试和生产构建 |

模拟输入位于 `src/tracking/mock-tracking.ts`，共享类型位于 `src/shared/contracts.ts`。样本按点击离散生成，不模拟实时帧率；`inferenceMs = 0` 和相等的采样／接收时间仅为模拟字段，不能当作追踪测量。
