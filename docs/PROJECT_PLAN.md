# 项目计划与验收

状态日期：2026-10-24。当前仅建立启动文档；应用骨架、功能代码和实机实验均未开始。

## 目标与推进方式

基础完成标准是：在网页摄像头画面中手动校准桌面透视面板，双手同时控制单曲的音量与低通滤波，并在两台桌面 Edge 笔记本上分别完成约 10 分钟体验。

二维矩形面板、单手和只有播放／暂停／音量的版本是中间 MVP。桌面对齐与双手阶段是必做内容；双音轨、搓碟、自动对拍和丰富 3D 效果属于之后的扩展。

不设日期、工时或固定人员排期。谁有空谁认领一个可验证的小任务。状态使用“未开始／已认领／进行中／待验证／完成／受阻”；只有已有验收证据才能标记完成。

## S0：最小工程与共同基础

- 建立 Vite、React、TypeScript 工程，统一 Node/npm 版本和一个锁文件；采用满足所选工具链要求的稳定版本。
- 将[接口草案](INTERFACES.md)中当前阶段需要的类型落实到共享代码，提供模拟输入，方便两条开发路线独立工作。
- 提供类型检查、lint、逻辑测试和构建命令，并把实际命令写入 README；当前不假定这些命令已经存在。
- 先合并公共基础，再开展并行模块工作。验收：两人能从同一提交安装、启动并运行已提供的检查。

## S1：摄像头与手部追踪

**目标：** 证明内置摄像头和实际机位适合后续桌面双手交互。

- 制作只有预览、21 点骨架、指尖光标、状态和性能数据的实验页；不先制作完整 DJ 外观。
- 在 Edge 比较 CPU／GPU、640 档与 720p 档请求、2～3 种实际机位。记录最终取得的尺寸、帧率，不能把请求值当实际值。
- 约 10° 只是候选角度。检查手腕、全部指尖和完整拖动轨迹是否入镜，以及用户能否舒适看屏幕。
- 从此阶段就测两只手同时入镜、第二只手干扰、手背／侧手、捏合、遮挡、正常室内光与逆光，记录可用环境边界。
- 同时只处理一个推理请求，忙时跳过旧帧。只采集本地聚合指标，默认不录制摄像头。

**初始门槛：** 在明确要求手位于有效区域的测试片段中，有效指针结果占采样帧至少 95%；有效结果频率至少 20 Hz；应用内采样到结果返回的 p95 不高于 100 ms。分别报告单手和双手配置，不将某一配置成绩推广到另一配置。

若不达标，先调整机位、光照、分辨率与目标区域并重测。仍不可用时记录限制，讨论姿势或范围调整；不擅自采购硬件，也不能将未通过的实验标记成功。

## S2：单手按钮与推子

- 使用两个大测试按钮和一个宽推子；确定食指定位、捏合阈值、平滑、防抖与有效命中区域。
- 验证初始已捏合不触发、按住不重复触发、抓取不跳值、移出控件仍保持拖动、丢手取消与松手后重新激活。
- 单手阶段同一时间只有一只手控制。第二只手不得突然抢占已有抓取。

**每位测试者：** 30 次按键、20 次完整拖动、2 分钟无操作意图的自然动作、10 次离开／重新入镜。

**初始门槛：** 首次按键成功率 ≥90%；无跳变拖动完成率 ≥90%；无操作意图的 2 分钟内误触 ≤1 次；无按住重复、抓取卡住或重入跳变。静止 5 秒时，光标偏移的 p95 半径小于目标宽度的 10%，推子数值波动不超过满量程的 2%。

统计首次成功与重试次数；不能只保留成功片段。指标定义、有效区域和调整过的参数随实验记录保存。

## A1 与 S3：本地音频、鼠标控制及单手 MVP

A1 可与 S1／S2 并行：按照共同接口加载本地文件，以鼠标／键盘验证播放、暂停、音量和状态反馈。S3 再连接真实手势。

- 基线文件为 MP3 和常见 PCM WAV；扩展名不保证编码可解码，坏文件和不支持格式应明确报错。
- 首次实际点击／按键启用音频，处理浏览器拒绝播放的情况；界面反映真实播放状态。
- 换曲暂停旧曲并重置位置，新曲保持就绪而不自动播放；连续快速换曲只保留最后一次有效选择。
- 检查丢手冻结参数但不中断音乐，以及鼠标接管、权限拒绝、摄像头占用、窗口变化、停止与重新启用。

**验收：** 两台 Edge 各体验约 10 分钟，包含加载两种基线格式、反复播放／暂停与音量拖动；无崩溃、持续音频卡顿、抓取状态卡死或资源重复创建问题。误触、重试和异常必须记录。通过这一阶段仅表示单手 MVP 可用。

## S4：桌面透视与低通滤波（必做）

- 提供四角手动校准；用户可以先调整相机和屏幕角度，再让面板四角对齐画面中的桌面区域。
- 使用同一正反透视变换完成视觉显示和指尖命中。保持面板内部控件坐标不变。
- 拒绝交叉、退化或过度压扁的四边形，保留上一次有效校准。校准期间取消抓取、暂停手势操作。
- 增加低通滤波推子及明确的启用状态，验证参数映射和变化平滑。

**验收：** 已知四角与内部五个测试点的映射正确，正反变换误差 ≤1 CSS 像素；实机透视面板近端和远端目标首次命中率 ≥90%；调整机位后可以重新校准。窗口尺寸变化后显示和命中仍一致。滤波能够产生可听变化，启停或调节无明显点击杂音。

手抬高可能产生视差；本阶段按指尖在图像中的位置操作，不承诺物理触桌、真实深度或真实遮挡。

## S5：双手并行与基础终态（必做）

- 两只手拥有独立指针和抓取状态，同一控件只允许一个所有者；任何一只手都可选择空闲控件。
- 同时调节音量和滤波；一只手丢失只冻结它的参数，另一只手继续工作。
- 测试交叉、遮挡、第二只手进入、同时争抢同一控件、分别离开与恢复；身份不明确时取消相关抓取，不能交换控制权。

**每位测试者：** 20 次双手并行调节，成功率 ≥90%；10 次交叉／丢手／重入测试无串控、抢占或恢复跳变，允许明确取消并提示重新抓取。

**最终验收：** 在完成桌面透视校准、开启真实音乐和滤波的完整场景中，两台 Edge 分别运行约 10 分钟；复测 S1 性能门槛与核心交互门槛。仅单手成功、仅模拟输入成功或只有视觉动画，都不能替代本阶段。

## 验证记录与后续扩展

每次实验至少记录设备与浏览器版本、机位描述、实际视频设置、追踪配置、试验次数、成功率／误触次数、p50／p95 耗时、现象和结论。机器信息避免包含用户名或个人目录。

“采样到结果”不包含全部摄像头曝光、画面呈现和声卡输出延迟；真正端到端延迟另测，同时记录跟手感和疲劳。所有数值都是暂定验收门槛，不是已测成绩；调整门槛需保留原因与前后结果。

逻辑测试覆盖坐标、状态机、捕获、参数和双手归属；实机验证覆盖机位、手感、浏览器及实际声音。阶段完成时更新本表和相关文档。

基础终态之后再评估双音轨、crossfader、搓碟、保音高变速与 3D 美化；每项先做独立验证，不默认现有单曲架构已解决其音质和性能问题。
